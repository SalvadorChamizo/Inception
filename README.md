# Inception

Short Description
-----------------

Inception is a containerized LEMP-style stack for running a WordPress site locally using Docker. It provides reproducible service definitions for Nginx, PHP-FPM/WordPress, and MariaDB, with optional services for Adminer, FTP, Redis, and uptime monitoring.

Key Features
------------

- Containerized services defined with Dockerfiles and Docker Compose
- Initialization scripts for database and application setup
- Service configurations (Nginx, PHP-FPM, MariaDB) tailored for local development
- Optional add-on services: Adminer (DB UI), FTP server, Redis, Uptime-Kuma
- Persistent volumes for data durability

Tech Stack
----------

- Frontend: Nginx (serves static assets, reverse proxy)
- Backend: PHP-FPM, WordPress (PHP)
- Database: MariaDB
- DevOps / Orchestration: Docker, Docker Compose
- Optional services: Adminer, FTP server, Redis, Uptime-Kuma (found under `srcs/requirements/bonus`)

Architecture & Design
---------------------

The repository uses Docker Compose to orchestrate a small suite of services:

- Nginx acts as a reverse proxy and static-file server
- A PHP-FPM container runs WordPress PHP code
- MariaDB provides persistent MySQL-compatible storage
- Optional services (Adminer, FTP, Redis, Uptime-Kuma) are included for convenience and testing

Each service is built from a local Dockerfile to keep builds reproducible and customizable.

Getting Started
---------------

Prerequisites
- Linux, macOS, or Windows with WSL
- Docker Engine (latest stable) installed and running
- Docker Compose (v2 plugin `docker compose` or `docker-compose`)
- Basic command-line familiarity

Note: If specific ports or credentials are required, review `srcs/docker-compose.yml` and the `.env` file generated by `create_env.sh`.

Installation

1. Open a shell in the repository root and move to the `srcs` folder:

```bash
cd srcs
```

2. Generate environment variables (this creates a `.env` file or similar configuration used by Compose):

```bash
./create_env.sh
# or, if required, make it executable:
# chmod +x create_env.sh && ./create_env.sh
```

3. Build and start the services:

```bash
# Using the docker compose plugin
docker compose up -d --build

# Or using docker-compose (if installed)
docker-compose up -d --build
```

Running the project
-------------------

- Check running containers and logs:

```bash
docker compose ps
docker compose logs -f <service-name>
```

- Stop and remove containers (optionally remove volumes):

```bash
docker compose down        # stops containers
docker compose down -v     # removes volumes (data will be deleted)
```

Usage
-----

- Open the web service in your browser at `http://localhost` (confirm the port mapping in `srcs/docker-compose.yml` if the service is bound to a non-standard port).
- WordPress admin: `http://<host>/wp-admin`.
- Database UI (Adminer): if enabled, typically exposed on a specified host port (check `docker-compose.yml`); credentials are taken from the generated `.env`.
- To dump or restore the database, use `docker exec` against the MariaDB container and `mysqldump` / `mysql` to export/import SQL.

What I Learned / Technical Challenges
-------------------------------------

- Building reproducible Docker images for each service and keeping configuration isolated
- Correctly configuring Nginx to proxy PHP requests to PHP-FPM and serve static assets efficiently
- Handling file and directory permissions between host and containers (WordPress uploads, database files)
- Ensuring ordered initialization of services and idempotent initialization scripts for MariaDB and WordPress
